2026-10-15 · 一条 15 分钟口播视频的制作过程中

同一份任务书，三个模型写同一段动效代码

视频的结构和编排由 Claude Opus 5.5 设计，画面代码交给别的模型写。第一版代码被视频作者评为“太简单、太一般”，于是拿同一个题目让三个模型各写一遍：Cursor 里的 Grok 4.7，以及小米 Token Plan 里的 MiMo v2.6 Pro 和 Flash。下面是它们的成品、过程数据、做法，和这次对比不够公平的地方。

先看成品

题目是整条视频里的两个场面：S05 邮件龙卷风（讲者有多个网店和两个猫舍、邮件很多，agent 接上邮箱后替他汇总订单、发货、回复和扣款）和 S26 按难度派模型（讲者转述马斯克的说法：简单任务走小模型，困难任务走大模型，再分给 Opus 和 Suno 这类模型）。三个模型拿到的任务书逐字相同，都渲成 720P、60fps，声音是整片混音里对应的那一段（口播和背景音乐）。

视频作者怎么评价

以下是看过三组成品后的原话，没有改写。

“做的代码是形象更好，但是龙卷风转的太快了。……漏斗那一块，小米做这个的就很好。……小米没做[邮件分类]。”说的是 MiMo Pro
“Grok做的龙卷风转速慢，但是那个邮件什么的不够清晰。但是Grok做的还有进一步的动画，就是邮件分类。……漏斗那一块，Grok做的是3D化的，但看上去很差。”说的是 Grok 4.7
“这个Flash的效果非常好呀，是这里面最好的。”说的是 MiMo Flash
“各有千秋吧，大差不差。”“我觉得速度都很慢。”

它们各自怎么做的

Grok 4.7

  • S05：全屏 WebGL2 琥珀螺旋慢转，three.js 的 96 张信封沿螺旋公转，带拖尾，四列玻璃槽用弹簧长出来。
  • S26：紫色数据流着色器，玻璃漏斗、喉管、会摆的挡板，右管分叉成 Opus 和 Suno。
  • 自己写下的不足：信封落地后叠成薄片，四个管道名同时出现会重叠。

MiMo Pro

  • S05：五层常驻——体积光涡、168 封信封乘六条螺旋臂、速度拉丝、四块玻璃柱里程计、逐字标题与冲击波。
  • S26：右半屏是派模型机器，任务卡“下落过冲、被挡板拨开、沿管滑下”三段式，证据帖用代码画。
  • 写了一个共用库：弹簧、冲击波环、逐字物理入场、镜头余震、确定性粒子。

MiMo Flash

  • S05：同样五层常驻，132 封信封带四层拖尾子帧，透视相机随拍呼吸、爆点推近。
  • S26：SVG 机器，每张卡过冲的挡板，三次贝塞尔管道里常驻流动的数据包。
  • 自己写下的取舍：体积光是二维混合近似，漏斗偏“云团”；机器缩到 60% 后管名字号偏小。

这次对比不够公平

相同的部分：三份任务书除了文件名前缀，逐字相同（用文本比对核实过）；Pro 和 Flash 在同一条命令、同一套允许工具下跑，只换了模型名。

不相同的部分：

  • 后跑的看到了先跑的。任务书只禁止改已有文件，没有禁止读别人的。从会话记录看：
Grok 先跑，没有参照→ Pro 开头读了 Grok 的说明和迷你时间线→ Flash 读了 Pro 的说明、两份迷你时间线和运行日志
  • Pro 和 Flash 的 S05 都是“体积光涡 + three.js 信封螺旋臂 + 速度拉丝 + 玻璃柱里程计”的五层结构，Flash 很可能参考了 Pro 的说明；会话记录里没有 Flash 读 Pro 场面代码全文的痕迹，只看到它 grep 过 Pro 代码里的元素注册行。
  • Grok 跑在 Cursor 的代理里，Pro 和 Flash 跑在 Claude Code 里，两边的工具集和提示不同。
  • 每个模型只跑了一次，场面只有两个，评价是视频作者的主观判断。

所以能说的是：同一道题，三个模型都交得出像样的画面，各有长短；说不出的是“Flash 比 Pro 强”，因为 Flash 是最后一个，手里有前面两个的说明。要得到干净的对比，需要各自在互相看不到对方文件的目录里重跑。

顺手记一个坑：怎么让 Claude Code 用小米 MiMo

小米的端点是原生的 Anthropic 兼容接口，直接用 curl 调用没有问题。但在已登录 Claude 订阅的机器上，用 Claude Code 指向它，会一直返回 401。原因是 Claude Code 把本机的订阅登录凭据一起发给了小米。给它一个空的配置目录就通了：

CLAUDE_CONFIG_DIR=/path/to/empty-dir \
ANTHROPIC_BASE_URL=https://token-plan-cn.xiaomimimo.com/anthropic \
ANTHROPIC_API_KEY=<你的 Token Plan 密钥> \
ANTHROPIC_MODEL=mimo-v2.6-pro \
claude -p "任务描述" --model mimo-v2.6-pro

另一个小坑：给 --allowedTools 传多个值时，任务描述要写在它前面，否则会被当成工具名吞掉。

接下来

视频作者同意让 Opus 写“动效分镜表”：每一场每一拍什么动、怎么动、对哪个词、配什么声音，执行的模型照表写代码。两版试写里的差别，转速、邮件是否清晰、有没有分类动画、漏斗要不要 3D，都会在表里写死，不再让执行的模型各自猜。表已经写完，下一步是先做共用的角色和舞台板，让视频作者看过样张再铺开。
